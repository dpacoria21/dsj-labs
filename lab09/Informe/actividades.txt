SOLUCIÓN DE ACTIVIDADES
Se desarrolló la aplicación Solar en Unity 6000.4.9f1 con Vuforia Engine 11.4.4. La aplicación reconoce la imagen SolarSystem.jpg como marcador y muestra sobre ella un planeta del sistema solar. Los botones Previo y Siguiente cambian el planeta visible. El proyecto se encuentra en la carpeta lab09/Solar del repositorio.
§ Creando el proyecto en Unity
Paso 1. Se verificaron los módulos instalados en Unity Hub. La versión 6000.4.9f1 cuenta con Android Build Support, OpenJDK y Android SDK & NDK Tools, necesarios para compilar la aplicación para Android.
[[IMG p01_hub_installs]]
Figura 1. Versiones de Unity instaladas. Unity 6.4 (6000.4.9f1) incluye el módulo de Android.
[[IMG p01_modulos_android]]
Figura 2. Módulos de Unity 6.4. Android Build Support, OpenJDK y Android SDK & NDK Tools figuran como instalados.
Paso 2. Se creó el proyecto 3D Solar dentro de la carpeta lab09. Se empleó el pipeline de render integrado, ya que los materiales del paquete SolarSystem usan el shader Legacy Diffuse y así no fue necesario convertirlos.
[[IMG p02_hub_proyecto]]
Figura 3. Proyecto Solar en Unity Hub, con la plataforma Android y el editor 6000.4.9f1.
Paso 3. Se eliminó la Main Camera de la escena, porque su función la cumple la ARCamera de Vuforia. En la jerarquía final solo quedan la luz direccional, la ARCamera, el ImageTarget, el Canvas y el EventSystem.
[[IMG p03_jerarquia]]
Figura 4. Jerarquía de la escena SolarAR sin la Main Camera.
§ Cambiar de plataforma a Android en Unity
Paso 1. Se abrió la ventana File > Build Profiles.
[[IMG pp1_menu_file]]
Figura 5. Opción Build Profiles del menú File.
Paso 2. Se seleccionó Android y se pulsó Switch Platform. Android aparece como plataforma activa.
[[IMG pp2_build_profiles]]
Figura 6. Build Profiles con Android como plataforma activa y la escena SolarAR en la lista de escenas.
Paso 3. En Player Settings > Other Settings > Graphics API se desactivó Auto Graphics API y se eliminó Vulkan. Solo queda OpenGLES3.
[[IMG pp3_graphics_api]]
Figura 7. Graphics API con OpenGLES3 como única opción.
Paso 4. En Minimum API Level se seleccionó Android 10.0 (API level 29). La guía indica Android 6.0 (API 23), pero Unity 6.4 no admite niveles inferiores a 25 y Vuforia 11.4 detiene la compilación si el nivel es menor que 29. También se configuró IL2CPP con ARM64, como exigen Vuforia y Google Play.
[[IMG pp4_min_api]]
Figura 8. Minimum API Level en Android 10.0 (API level 29) y Scripting Backend IL2CPP.
Paso 5. Se cerraron las ventanas de configuración.

§ Creación del Script
Paso 28. En Assets se creó la carpeta Scripts.
Paso 29. Dentro de Scripts se creó el script en C#. La guía lo nombra MultiTargetsVuforia, pero la clase se llama MultiTargetVuforia. Unity exige que el archivo y la clase tengan el mismo nombre, por lo que el archivo se llamó MultiTargetVuforia.cs.
[[IMG p29_scripts]]
Figura 25. Carpeta Scripts con MultiTargetVuforia.
Paso 30. Se abrió el archivo en el editor de código.
Paso 31. Se escribió el código de la guía. En Start, el script cuenta los hijos del ImageTarget y guarda la posición del modelo inicial. ChangeARModel recibe −1 o 1: oculta el modelo actual, calcula el índice del siguiente y muestra ese modelo. Si el índice queda fuera de rango, pasa al otro extremo de la lista.
[[IMG p31_codigo]]
Figura 26. Código de MultiTargetVuforia.
Paso 32. Se guardó el archivo y se volvió a Unity.
Paso 33. Se agregó el script MultiTargetVuforia al ImageTarget.
Paso 34. Se arrastró el prefab Earth al campo Start Model para que la aplicación empiece mostrando la Tierra.
Paso 35. Se activó el prefab Earth para que sea visible.
[[IMG p33_multitarget_script]]
Figura 27. ImageTarget con el componente Multi Target Vuforia y Earth como Start Model.
§ Agregar el método ChangeARModel al evento Click de los botones
Paso 36. En ButtonPrevio, dentro de On Click, se pulsó + y se arrastró el ImageTarget al campo de objeto.
Paso 37. Se eligió la función MultiTargetVuforia.ChangeARModel con el valor −1.
[[IMG p37_onclick_previo]]
Figura 28. On Click de ButtonPrevio: ChangeARModel con el valor −1.
Paso 38. En ButtonSiguiente se repitió el procedimiento con el valor 1.
[[IMG p38_onclick_siguiente]]
Figura 29. On Click de ButtonSiguiente: ChangeARModel con el valor 1.
Paso 39. Se ejecutó la aplicación en el editor. Vuforia se inició con la licencia y el botón Siguiente cambió el modelo de la Tierra a Marte. El nombre del modelo activo aparece en la parte superior. Vuforia oculta los planetas mientras no reconoce el marcador, por lo que el reconocimiento se comprobó en el celular.
[[IMG p39_play_mode]]
Figura 30. Play Mode con Vuforia iniciado. Al pulsar Siguiente, el modelo activo pasa a ser Marte.
§ Generar el Apk
Paso 40. Desde File > Build Profiles se pulsó Build.
[[IMG p40_build_boton]]
Figura 31. Botones Build y Build And Run de Build Profiles.
Paso 41. Se eligió la carpeta Builds. Unity generó el archivo Solar.apk, de 58 MB, que incluye la biblioteca de Vuforia para ARM64. El APK se instaló en un Samsung Galaxy A15 con Android 16 y se apuntó la cámara a la imagen SolarSystem, mostrada en el monitor. Al reconocerla, la aplicación muestra el modelo activo sobre la imagen.
